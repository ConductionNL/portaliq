## Scope

A portal subject can now own a row through a list field. The direct scope check in the reader and the writer matches when the stored value equals the subject's scoping value or is a list that contains it, and fails closed on every other shape.

Before this, `PortalObjectReader::verifyScope` and `PortalObjectWriter::fetchOwnedObject` compared `(string)($row[$scopeField] ?? '')` with the scope value. A list casts to `"Array"`, so every list-scoped row was dropped after OpenRegister had already returned it (OpenRegister filters an `array` property by containment, `MagicSearchHandler::applyJsonArrayFilter`).

## Why

learniq declares list scope fields that read empty in the portal today:

- `studentSubmissions` and `createSubmission` scope `submission` by `learnerRefs` (`type: array` in `learniq_register.json`).
- `parentChildren` (learniq PR 928, `portal-contribution-guardian-audiences`, merged today) scopes `learner-profile` by `guardianRefs`. Its `design.md` assumes portaliq does the direct containment match.

Source: finding 1 in the r2-portal lane log (`pq-guard/LANE-LOG.md`, "Finding for the orchestrator"). learniq needs no change.

## What changed

- `lib/Service/PortalScopeMatch.php` (new trait): the one rule. A string or integer matches when equal. A list matches when one string or integer element is equal. An empty scoping value, null or absent, an empty list, an associative array, a nested list and any other type never match. Comparison is strict.
- `PortalObjectReader::verifyScope` uses it. That covers the list read, the detail read, and the portalAccount lookup behind `scopeClaim`.
- `PortalObjectWriter::fetchOwnedObject` uses it, so the verified update, mark-read and status transitions match the same way.
- `PortalObjectWriter::updateObject` re-stamps a verified list with the stored list itself. A patch can no longer overwrite `["learner-1", "learner-2"]` with `"learner-1"`, and a client value never wins.
- `PortalObjectWriter::createObject` stamps `[subjectRef]` when the target schema types the scope field as `array` (read through the optional `PortalSchemaReader`, the pattern `ActionConfigNormaliser` already uses). Otherwise, or when the schema cannot be read, it stamps the single value as before.
- One hardening: an empty scoping value used to match rows whose scope field was absent or empty. It now matches nothing. No caller passes an empty value on purpose.
- README contract v2 section, main spec change list, and the openspec change `portal-scope-list-membership`.
