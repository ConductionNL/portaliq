# Roles for content and actions

A communication team can edit the site. A service desk can create resident accounts. Only you change settings. Portaliq lets a Nextcloud group do one job without making its members administrators.

## Who may edit pages and the menu

Open **Administration settings**, then **Portaliq**, then **Page editors**. Pick the groups. Members can create, change and delete pages, the menu, the media library and the maintenance notices. Without a group, only administrators can.

## Who may do an action

Open **Administration settings**, then **Portaliq**, then **Actions**. Each action has a name, a line that says what it lets someone do, and a group picker.

| Action | What it lets someone do |
| --- | --- |
| Create and manage portal accounts | Invite residents and organisations, claim and revoke accounts |
| Ask a partner organisation for input | Send a case task to a partner |
| Review proposed changes | Accept or refuse changes residents propose to their own details |
| Answer access requests | Grant or refuse access to a record |
| Send emergency messages | Push an urgent message to guardians |
| Write news items | Create, change and publish news |
| Send newsletters | Send a newsletter to a group |
| Manage activities | Create and change activities |
| Manage events | Create and change school events |
| Create polls | Ask guardians a question |

An empty picker reads "Only administrators". Administrators always keep every action. A group you pick that no longer exists is dropped when you save.

## When you upgrade

A new release can add an action. It arrives as "Only administrators". The grants you set stay as they are.
